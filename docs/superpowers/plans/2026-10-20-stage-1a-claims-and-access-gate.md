# Stage 1a Implementation Plan: truthful status language and the temporary access gate

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. One fresh subagent per task; the parent re-runs every teeth check itself before dispatching the next. Steps use checkbox (`- [ ]`) syntax for tracking. The user runs every `git add` and `git commit`; no task commits.

**Goal:** remove every claim the record does not back from the public site and the record screen, and make a configured pilot profile unobtainable without a valid access session issued from a server-side secret, while authorised local access keeps working.

**Architecture:** one pure module (`lib/access.ts`) decides access from the environment, the cookie header and the request time; `middleware.ts` enforces it before rendering and sets cache headers; the dashboard page enforces it again before reading the profile. A second pure module (`lib/coverage.ts`) derives the four coverage statuses from the pack, the ledger and the source register. Copy corrections are plain edits guarded by a source-scanning test.

**Tech Stack:** Next.js 15.5 (App Router, middleware on the Edge runtime, route handlers on Node), React 19, zod, vitest (node environment), Web Crypto for HMAC. No new runtime dependency.

**Design:** `docs/superpowers/specs/2026-10-20-stage-1a-claims-and-access-gate-design.md`. Read it first; every requirement there binds every task here.

### Task 1: the pure access module

**Files:**
- Create: `frontend/web/lib/access.ts`
- Test: `frontend/web/test/access.test.ts`

**Interfaces (produces):**
- `ACCESS_SECRET_ENV = 'DATASTRATA_PILOT_ACCESS_SECRET'`, `ACCESS_REVOKED_BEFORE_ENV = 'DATASTRATA_PILOT_ACCESS_REVOKED_BEFORE'`, `ACCESS_COOKIE = 'ds_pilot_access'`, `ACCESS_SESSION_SECONDS = 43200`, `ACCESS_SECRET_MIN_LENGTH = 16`, `ACCESS_COOKIE_PATH = '/dashboard'`.
- `readAccessConfig(env: Readonly<Record<string, string | undefined>>): AccessConfig` where `AccessConfig = { ok: true; secret: string; revokedBefore: Date | null } | { ok: false; problems: string[] }`. Problems are sentences naming the variable, never its value: unset, blank after trimming, shorter than 16 characters, or a revoked-before value that is not an ISO-8601 instant.
- `readAccessConfigAt(env, now: Date): AccessConfig`: `readAccessConfig`, then the time rule. The configuration is unusable when `revokedBefore.getTime() > now.getTime()`, and an equal instant is usable. The problem is one sentence that names `DATASTRATA_PILOT_ACCESS_REVOKED_BEFORE` and prints neither the instant nor the server time, and it joins the other problems in the same list. Nothing else decides configuration: `accessDecision` and Task 3's handler call it, each with its one captured request time.
- `issueAccessToken(secret: string, now: Date, nonce: string): Promise<string>` returning `v1.<issuedAtMs>.<expiresAtMs>.<nonce>.<base64url signature>` where the signature is HMAC-SHA-256 over `v1.<issuedAtMs>.<expiresAtMs>.<nonce>` under the key `HMAC-SHA-256(secret, 'datastrata-pilot-access-v1')`, computed with Web Crypto only.
- `verifyAccessToken(token: string, secret: string, now: Date, revokedBefore: Date | null): Promise<TokenVerdict>` where `TokenVerdict = { ok: true; issuedAt: Date; expiresAt: Date } | { ok: false; reason: 'malformed' | 'bad_signature' | 'expired' | 'revoked' }`; the signature is checked with `crypto.subtle.verify` before any field is trusted; `expiresAt <= now` is expired; `issuedAt < revokedBefore` is revoked.
- `passphraseMatches(submitted: string, secret: string): Promise<boolean>` in constant time without Node-only APIs: a fresh random HMAC key is imported, the HMAC of the secret is computed with `sign`, and `subtle.verify` checks it against the submitted bytes.
- `cookieValue(cookieHeader: string | null, name: string): string | null`.
- `accessCookie(token: string, request: { https: boolean; production: boolean }): CookieAttributes` and `clearedAccessCookie(request): CookieAttributes` where `CookieAttributes = { name: string; value: string; httpOnly: true; sameSite: 'strict'; path: '/dashboard'; maxAge: number; secure: boolean }`; `secure` is `https || production`; the cleared cookie has `maxAge: 0` and an empty value.
- `accessDecision(input: { env; cookieHeader: string | null; now: Date }): Promise<AccessDecision>` where `AccessDecision = { kind: 'unconfigured'; problems: string[] } | { kind: 'denied'; reason: 'no_session' | 'malformed' | 'bad_signature' | 'expired' | 'revoked' } | { kind: 'allowed'; expiresAt: Date }`. It judges the configuration with `readAccessConfigAt(env, now)`, the same `now` it judges the token at.
- `class AttemptLimiter { constructor(limit = 5, windowMs = 900000); allowed(key: string, now: Date): boolean; recordFailure(key: string, now: Date): void; }` keeping failure timestamps per key in memory and forgetting those older than the window.
